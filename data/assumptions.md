# 假设登记表

> 本文件是 `src/` 下每一个非目录数据常量的**唯一出处**。代码中不允许出现未登记的魔法数字。
> 口径纪律与本项目其他部分一致：**查不到就写「未查到」，不用看起来合理的数字替代。**

## A · 清洗与去重

### A-01 相似度判定
| 项 | 值 | 类型 | 依据 |
|---|---|---|---|
| 判定方式 | 中文按字 bigram 的 Jaccard 相似度 | 公开可查 | 无第三方依赖下最稳健的中文短文本相似度做法 |
| 完全重复阈值 | 1.00（集合相等） | 公开可查 | 归一化后的上界 |
| 合并阈值 | ≥ 0.45 | **占位待实测替换** | 工程取值。真实项目须用历史工单标注集校准；阈值改动会直接影响合并结果 |
| 指代代词表 | 这个 / 那个 / 他们那边 / 这边 / 该 / 其 | 行业典型值 | 中文需求文本的高频指代词 |

### A-02 噪声清洗
| 项 | 值 | 类型 | 依据 |
|---|---|---|---|
| 表情与语气词 | 列表形式，见 `cleaner.py::NOISE_TOKENS` | 行业典型值 | 邮件与工单中的高频口水词 |
| 标点归一 | 全角转半角 + 去除重复空格 | 公开可查 | 文本预处理标准做法 |

### A-03 字段抽取
| 项 | 值 | 类型 | 依据 |
|---|---|---|---|
| 芯片型号匹配 | 全串匹配 + 边界约束 | 公开可查 | 型号含数字与连字符，须防止 `TX8` 误命中 `TX81` |
| 模型名匹配 | 同上 | 公开可查 | 模型名含小数点与连字符 |
| 框架版本 | `名称 + 空格 + 版本号` 组合正则 | 公开可查 | 需求中通常写「pytorch 2.1」「vLLM 0.6」 |
| 抽不到的字段 | 填「未提取到」，**不猜** | — | 项目核心纪律 |

### A-04 问题类型分类
| 类型 | 判定依据 | 说明 |
|---|---|---|
| `oom` | 出现 OOM / out of memory / 显存爆 / 显存不够 | 显存不足类 |
| `operator_fallback` | 出现 fallback / 算子不支持 / 吞吐掉 / 利用率低 | 算子适配类 |
| `capability_question` | 问「能不能支持 / 支不支持 / 能不能用」 | 能力咨询类 |
| `multi_card_question` | 出现 加卡 / 几张卡 / 多卡 / 切分 / 横向扩展 | 多卡方案类 |
| `finetune_question` | 出现 微调 / LoRA / lora | 微调支持类 |
| `delivery_timeline` | 出现 交付 / 排期 / 什么时候能 | 交付承诺类 |
| `doc_gap` | 出现 文档 / 说明看不懂 / 步骤 / 拆分文档 | 文档缺失类 |

> 分类是**多标签**：一条需求可同时属于 `oom` 与 `capability_question`。
> 单标签分类会丢失信息，这正是原始需求「杂」的一种体现。

## B · 适配判定

### B-01 显存判定
| 项 | 值 | 类型 | 依据 |
|---|---|---|---|
| 需求口径 | 模型 `min_vram_gib` vs 芯片 `vram_gib` | 公开可查 | 取公开模型卡的量级，**为下界** |
| 运行时余量 | 1.15 | 行业典型值 | 覆盖激活值与碎片；**须按实际框架 profiling 校准** |
| 字段缺失时 | 判 `unknown`，不猜 | — | 核心纪律 |

### B-02 框架判定
| 项 | 值 | 类型 | 依据 |
|---|---|---|---|
| fallback 行为来源为 `unverified` 时 | 只输出「需实测验证」，不输出「不推荐」 | — | 责任对等原则：不能拿客户单方描述否定框架版本 |
| FlagOS 原生算子库 | 判「支持」，依据 S3 | 公开可查 | FlagGems 为官方仓库 |

### B-03 多卡判定
| 项 | 值 | 类型 | 依据 |
|---|---|---|---|
| 需求卡数 | ceil(模型最小显存 / 单卡显存) | 公开可查 | 向上取整到整数卡 |
| 切片方式 | 至少说明张量并行 / 流水并行 / 专家并行三种候选 | 公开可查 | 具体选型须研发确认，本工具不代为决策 |

## C · 明确不做的事

- **不做算力采购测算**（卡数成本、TCO、BOM）：那是 `ai-compute-presales-workbench` 的范围。
- **不做真卡实测**：本项目无算力卡，适配判定依据为公开资料 + 自拟样本。
- **不伪造内部数据**：不生成任何看起来像厂商内部测试结果或 Jira 真实数据的数字。
- **不代替研发做切片决策**：只列出候选方式与各自约束，决策权在研发。
- **不生成可直接投产的测试脚本**：输出的是**脚本骨架 + 阈值说明 + 失败判据**，
  具体阈值须按客户实际模型标定。
- **不含客户身份信息**：样本自拟并脱敏，行业只用通用分类。
- **不维护实时数据**：芯片与框架迭代快，`data/` 的抓取日期即数据时效边界。
